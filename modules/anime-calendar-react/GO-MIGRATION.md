# 新番日历后端 Go 迁移

## 评估

当前模块以 Fastify 注册 HTTP 路由，以 PostgreSQL 保存状态，以 Bangumi 作为数据源。页面和工作台组件通过 ToolNest Gateway 调用模块。宿主提交 `c5d3d54` 已支持 `runtime.kind: native` 和按操作系统、架构选择可执行文件，可用这条路径交付独立 Go 后端。开发以新番日历为本轮迁移对象。

Go 侧采用标准库 HTTP、时区和请求取消能力，以及与宿主一致的 pgx 系列数据库驱动。构建环境需要 Go 工具链，运行环境直接加载编译后的二进制。当前已测量归档大小。冷启动、空闲内存和档期读取尚无同负载基准数据。

## 功能与验收

| 能力 | 兼容要求 | 验证 |
| --- | --- | --- |
| 宿主运行 | 模块 ID、网关路径、内部 token、就绪响应与 release ID | 隔离宿主通过模块 API 安装、启用、升级、停用及回滚 |
| 档期列表与统计 | 现有响应字段、过滤、关注标记、列表与详情的字段差异 | 对同一份缓存比较 Node 与 Go 的 JSON，覆盖空结果、无效参数和航海王跨档期 |
| Bangumi 数据 | 搜索按实际页长翻页、轻量周历合并、按需详情、代理与失败时使用现有缓存 | 模拟上游的分页、非法响应、超时及详情失败 |
| 地区 | 显式国家、精确标签、制作公司及缓存修复 | 中国风标签和日本制作并存、跨缓存继承冲突与无来源陈旧记录 |
| 今日与周历 | 只读请求使用已保存数据，今日换日与周历手动刷新行为一致 | 时区边界、周日编号、关注/忽略与并发刷新 |
| 数据刷新 | 当前档期默认每日 04:00，下一档期和周历七天周期，可配置时间并保留失败重试 | 可控时钟和模拟上游验证，涵盖从关闭页面到下一轮的调度 |
| 通知 | 平台时区、公开地址、默认渠道、模板变量、档期和关注更新、单条或聚合及防重复 | 模拟平台记录标题、正文、渠道和幂等键，验证设置校验与失败重试 |
| 存量数据 | `anime_calendar_entities` 的集合和 JSON 字段兼容，保留设置、关注、历史、缓存和旧 JSON 导入 | PostgreSQL 中用 Node 写入后由 Go 读取和写回，再由 Node 读回 |
| 打包 | 通过当前发布入口生成原生模块包，统一版本及构建目标 | 检查归档内容及目标选择，在隔离宿主完成安装和网关烟测 |

## 实施顺序

1. 迁移领域规则和 Bangumi client，固化时间、类型、地区、集数和跨档期的边界用例。
2. 迁移状态仓库。复用已有表和集合，写事务成功后才更新进程内快照。批量写入变化的行并保留未知集合，便于回滚。
3. 迁移 HTTP 接口、缓存编排和调度。共享进行中的同档期刷新，限制上游请求时间，避免一次请求中重复建立代理连接。
4. 迁移平台设置与通知，逐项比对旧后端的行为。完成行为对照后切换 manifest 和打包流程。

后端切换前以隔离数据库验证升级和回滚。正式发布需要支持原生模块和带冒号 API 路径段的宿主。调度器使用固定时钟和模拟平台验证触发条件，宿主验收验证模块启用和升级后的就绪状态。

## 已实现与验证

- 原生包配置为 eager，模块启用后调度即可启动。每次运行同一任务完成后再检查下一轮。当前档期按平台本地日刷新，下一档期和周历按七天更新，失败任务间隔 30 分钟重试。
- 复用上游 HTTP 连接和 PostgreSQL 连接池，刷新按档期合并并发请求。数据库批量保存实际变化的行，事务提交后发布新的只读快照。
- Linux amd64、Linux arm64 和 Windows amd64 共用一个包。最终本地包 ZIP 14.56 MiB，解包 39.23 MiB。旧的单入口 Node 包约 0.75 MiB，原生包包含三个目标二进制，前端预算保持原值。
- 隔离 PostgreSQL 测试覆盖旧 JSON 导入、写失败后重试及数据库重开。模拟平台覆盖本地时间边界、公开模块链接、默认渠道和重复发送检查。
- 隔离 Linux 宿主用真实安装 API 验证 Node 0.1.53 → Go → Node。航海王关注与设置通过了网关对照，Go 修改的设置回滚后可读。该测试要求宿主允许 URL 路径段内的冒号，仓库内网关路径校验已对应调整。
- Windows amd64 从最终包解出可执行文件，连接隔离 PostgreSQL 后通过带内部令牌的就绪检查。Linux arm64 已交叉编译。

从模块仓库根目录复跑宿主测试：

```bash
node test/anime-go-upgrade.mjs /path/to/previous-node.tnmod /path/to/new-go.tnmod
```

通过 `TOOLNEST_GO_TEST_IMAGE` 指定带原生运行时和网关修复的 ToolNest 镜像。历史 Node 发布包可用于运行时回滚。仓库中的 Node 后端源码由 Go 后端替代。
