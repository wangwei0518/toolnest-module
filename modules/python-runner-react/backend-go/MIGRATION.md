# Python Runner 后端迁移至 Go

Python Runner 的现有 Node 服务负责项目文件、PostgreSQL、Python 子进程、定时调度、常驻任务和通知。Go 原生模块接管这些业务，用系统 Python 或项目虚拟环境运行脚本。

| 边界 | 迁移设计 |
| --- | --- |
| 接口 | 在 Go 注册同一套 HTTP 路由。保留请求字段、状态码、错误结构、日志下载和 SSE 格式。以现有 React API 调用和 Node 集成测试为对照。 |
| 数据 | 直接复用现有 PostgreSQL schema、`pr_schema_migrations` 版本和目录布局。初始化 SQL 嵌入 Go 二进制，已有版本跳过。用原版写入真实测试数据，验证 Go 读取与写回，再切回原版核对。 |
| 进程 | 通过参数列表启动 Python。保留限制后的环境变量、虚拟环境路径、PID、超时、停止及日志字节上限，区分 Unix 和 Windows 的进程树终止。 |
| 调度 | 保留 eager、时区、Cron、一次性任务、超时及补跑规则。启动后由 Go 后端驱动，验证全程不打开网页时也能触发。关闭时先停调度，再清理运行任务与连接。 |
| 项目与权限 | 保留导入、更新、回退、预览、配置遮盖、安全扫描确认与依赖安装行为。沿用入口和归档的路径检查，验证上传与清理都限制在模块目录。 |
| 发布 | 清单切到 native，沿用模块 ID 和平台发布架构。完成接口及旧数据回归后，移除 Node 源码、依赖和打包引用，再用隔离平台导入验证升级、重启与回滚。 |

优先验证三类容易造成用户数据或任务状态变化的情况。升级时有运行中任务，调度器启动时有已到期任务，以及上传或依赖操作在中途失败。验证需包含中文多行 stdout 与 stderr，确认字符、换行和执行分组在切换后可读。

## 实施取舍

- 原生包带有独立 Go 二进制。实测 Linux amd64、Linux arm64 和 Windows amd64 的包分别约为 5.70、5.26 和 5.85 MiB。单架构压缩包预算为 7 MiB，React 资源继续使用各自原有预算。
- 模块启动时将之前中断的运行标为停止。已领取的一次性任务不会因重启重新执行。Cron 到期时若执行槽位已满，会在下一次轮询重试。支持原版日历表达式的 `L`、`#`、星期日别名 `7` 和 `H`。Go 按表达式稳定计算 `H` 值。
- 跨架构恢复需使用支持调用 Go 原生恢复入口的 ToolNest 平台版本。管理员确认后，Go 模块重建项目虚拟环境并用当前依赖清单重新安装；阻断风险会中止恢复。

## 验证方法

- Go race 测试和 vet。用独立 PostgreSQL 验证旧迁移记录、项目导入、风险确认、真实 Python 进程、多行 UTF-8 日志和独立于 HTTP 的到期调度。
- 构建三个单架构包和一个本地全架构包，检查各包入口和体积。
- 在独立 ToolNest 容器中通过 API 安装 Node 包、升级 Go 包、回滚原包并检查 operation。用相同项目核对虚拟环境复用、依赖安装、配置遮盖、常驻任务、源码更新与回退、日志与定时任务。恢复子测试模拟跨架构备份恢复后写入的待恢复标记，通过真实平台 API 重建环境和恢复模块。
