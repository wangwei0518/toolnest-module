# 背屏壁纸后端 Go 迁移

现有 Node 进程接收宿主转发的 HTTP 请求，从内部请求头取得用户身份，将原图、预览和导出存入用户目录，并用 `wallpapers.json` 保存作品和任务的状态。Sharp 负责解码、方向校正、裁剪、缩放及编码。浏览器负责把苹果实况和新导入的 GIF 转换为安卓动态照片，并在保存时输出裁剪后的 H.264 视频。

Go 进程沿用模块 ID、路由、鉴权头、状态字段、文件名和目录结构。按宿主原生模块协议打包 Linux amd64、Linux arm64 和 Windows amd64。进程监听宿主分配的回环端口，提供就绪检查和认证后的 HTTP 停止入口。卸载或升级发布包与用户数据目录分离，无需批量转换现有作品。

- 静态图片保留 JPEG、PNG、WebP 输入，PNG 导出和 WebP 预览，裁剪仍生成 976 × 596。保留 EXIF 方向校正。
- 历史 GIF 保留帧、延迟、循环和处置模式。新上传 GIF 继续由浏览器转换。安卓动态照片保留 JPEG、XMP、MP4 封装及关键帧时间。
- 并发控制覆盖索引写入、同一作品的裁剪和删除。输出先生成临时文件再替换，重启后恢复持久化的处理中任务。文件流保留 UTF-8 文件名和浏览器进度所需的长度字段。
- 用旧格式数据验证原图、预览、导出、裁剪和重启恢复。使用真实 HTTP 验证权限隔离、文件字节与响应头。部署验证覆盖打包目标、安装、原地升级及持久化。确认兼容后移除 Fastify、Sharp 后端与旧测试，再提交 GitHub。

在模块仓库根目录运行 `go -C modules/xiaomi-rear-wallpaper/backend-go test -tags nodynamic -race ./...`。要复验发布包升级，将旧 Node 包和新 Go 包传给 `node test/wallpaper-go-upgrade.mjs <旧包> <新包>`。脚本启动独立的 Docker 宿主，通过模块 API 安装和升级，比较原有文件、保存新取景并验证回滚。可用 `TOOLNEST_GO_TEST_IMAGE` 指定带原生运行时支持的 Linux amd64 平台镜像。
